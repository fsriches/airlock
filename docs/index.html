AIRLOCK
Binance Agent OS Mini Hackathon, Track A

Every trade passes six chambers.

Airlock sits between an AI trading agent and Binance. A plain instruction becomes a typed, hashed mandate that a human approves by typing the hash back. Only then is it sent, and every fill is checked against what was approved.

Why this exists

Binance's own docs say agents can hallucinate, act on stale data, or send wrong parameters. Airlock makes those mistakes cheap: a wrong price fails Evidence, an oversize order fails Lock, a bad fill is caught by Reconcile, and one command flattens everything.

Airlock never opens risk on its own. Every order that adds exposure comes from an intent that passed all chambers with a human approval bound to its hash. The supported production path is to run Airlock as a sidecar under Claude Code or Codex.

Replicate it in about a minute

You need Python 3.11 and a free Binance Spot Testnet key (testnet.binance.vision, sign in with GitHub). No real Binance account.

# get the code
git clone https://github.com/fsriches/airlock && cd airlock
pip install -r requirements.txt

# testnet key, never inside the repo
export AIRLOCK_HOME=$HOME/.airlock
echo '{"key":"...","secret":"..."}' > $AIRLOCK_HOME/binance_testnet.json && chmod 600 $AIRLOCK_HOME/binance_testnet.json

# the six chambers
airlock check                                   # EVIDENCE
airlock intent "buy 10 USDT of BNBUSDT market"  # MANDATE, prints the approval hash
echo "<hash>" | airlock yes                     # LOCK
airlock execute                                 # EXECUTE
airlock reconcile --order-id AIR-ORDER-...      # RECONCILE
airlock kill                                    # KILL
airlock verify                                  # ledger hash chain
